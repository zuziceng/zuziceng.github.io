6.3 UART API 详解

函数原型说明
uart_param_configesp_err_t uart_param_config(uart_port_t port, const uart_config_t *config)配置 UART 参数（波特率、数据位、校验、停止位、流控）
uart_set_pinesp_err_t uart_set_pin(uart_port_t port, int tx_io, int rx_io, int rts_io, int cts_io)将 UART 信号映射到指定 GPIO 引脚，UART_PIN_NO_CHANGE 表示不修改
uart_driver_installesp_err_t uart_driver_install(uart_port_t port, int rx_buffer_size, int tx_buffer_size, int queue_size, QueueHandle_t *queue, int intr_alloc_flags)安装 UART 驱动，分配接收/发送环形缓冲区
uart_write_bytesint uart_write_bytes(uart_port_t port, const void *src, size_t size)发送数据，返回发送的字节数
uart_read_bytesint uart_read_bytes(uart_port_t port, void *buf, size_t length, TickType_t ticks_to_wait)读取数据，超时参数控制阻塞时间
uart_flushesp_err_t uart_flush(uart_port_t port)清空接收缓冲区
uart_wait_tx_doneesp_err_t uart_wait_tx_done(uart_port_t port, TickType_t timeout)等待发送完成，确保数据全部发出

uart_config_t 结构体字段说明：

字段可选值说明
baud_rate9600, 115200, 921600 等波特率，收发双方必须一致
data_bitsUART_DATA_5_BITS ~ UART_DATA_8_BITS数据位长度
parityUART_PARITY_DISABLE / UART_PARITY_EVEN / UART_PARITY_ODD校验位：无/偶校验/奇校验
stop_bitsUART_STOP_BITS_1 / UART_STOP_BITS_1_5 / UART_STOP_BITS_2停止位长度
flow_ctrlUART_HW_FLOWCTRL_DISABLE / UART_HW_FLOWCTRL_RTS / UART_HW_FLOWCTRL_CTS / UART_HW_FLOWCTRL_RTS_CTS硬件流控（RTS/CTS）
rx_flow_ctrl_thresh0~127RTS 流控阈值，缓冲区剩余小于此值时发送 RTS 信号
source_clkUART_SCLK_APB时钟源（通常使用默认 APB 时钟 80MHz）

📚 知识扩展

编程知识回顾：

  • 异步串行通信：UART 是异步的，不需要时钟线。通信双方必须约定相同的波特率，一个起始位（拉低），5-8 个数据位，1 个停止位（拉高）。典型的是 8N1（8 数据位、无校验、1 停止位）。
  • 缓冲区管理：uart_driver_install 分配了硬件 FIFO + 软件环形缓冲区。uart_read_bytes 从环形缓冲区读取，超时参数决定了在没有数据时阻塞多久。理解这个机制有助于设计不会丢数据的通信逻辑。
  • 阻塞 vs 非阻塞：uart_read_bytes 的超时参数设为 0 表示非阻塞（立即返回），设为 portMAX_DELAY 表示阻塞直到收到数据。选择合适的方式取决于场景：轮询用短超时，等待命令用长超时。

重点掌握：

  • UART0 默认用作 printf 和 ESP_LOG* 输出（通过 USB 转串口芯片 CP2102）。如果要使用 UART0 与其他设备通信，需要重新配置引脚，但通常建议使用 UART1 或 UART2
  • uart_driver_install 的第三个参数是发送缓冲区大小（0 表示使用默认的 TX FIFO），第四个参数是接收缓冲区 — 可以根据数据量调整
  • 接收到的数据没有 \0 结尾符，需要手动加上才能作为字符串使用：buf[len] = '\0'

编程技巧：

  • 调试串口通信时，先用示波器或逻辑分析仪查看 TX/RX 波形，确认有信号但收不到数据通常是波特率不匹配
  • 使用 uart_flush 在初始化后清空缓冲区，避免上电时收到的乱码干扰程序逻辑
  • UART 接收建议用 FreeRTOS 队列配合 ISR，而不是在主循环中轮询读取，这对于高频率数据传输尤其重要
  • 如果需要更高的通信可靠性，可以启用硬件流控（RTS/CTS），但需要额外占用 2 个 GPIO
